# 段階2: 企画・差別化設計

## 前提チェック（チェックポイント）

1. `./ns show <テーマID>` でテーマを読む。
2. 状態が **「採用・企画待ち」「企画確認待ち」「企画確定」以外なら作業しない**。
   「このテーマはまだ採用されていません。画面で採用してから依頼してください」と伝えて終わる。
   （`import-plan` も同じ理由で拒否される。`./ns decide` を自分で実行して通してはいけない）
3. 最新の企画が「修正依頼中」なら、その「あなたのメモ・修正依頼」を最優先で反映した新しい版を作る。

## 手順

1. **テーマの根拠を読み直す**: 需要の根拠・競合・人間のメモ・判断ログ。
   `references/books/_書籍リスト.md` で「使う段階」に2を含む書籍を、`tools/pdftool find` で該当箇所だけ読む。
   目安: 無料/有料の境界と無料エリアの書き方 → note実践書2冊・『セールスコピー大全』、タイトル・見出し →
   『伝え方が9割』『ザ・コピーライティング』、切り口の発想 → 『AIを使って考える全技術』、体験・感情の乗せ方 → 『AI×感情でつくる売れる文章術』。
   書籍の技法は構成・表現の参考にとどめ、要約を企画の中身にはしない（詳細は CLAUDE.md の「参考書籍」）。
   セールス系の技法もこのスキルの「誇大表現は使わない」ルールの範囲内で使う。
   書籍を根拠にした主張は `claims` に `source.type: "book"`（url不要、`publisher` と `location` 必須）で入れる。
2. **追加で調べる**（WebSearch 10〜20回程度）:
   - 本文の核になる公的情報・一次情報（官公庁・公式サイト・統計）
   - 競合記事・無料記事が **何を書いていて、何を書いていないか**（検索スニペットや目次から）
   - 読者が実際につまずいている点（Q&Aサイト、ニュースのコメント要旨など）
   - 情報源のルールは note-research スキルと同じ（note の /search・/api 禁止、個別記事の閲覧は5ページまで、Xのスクレイピング禁止、URL・数字の捏造禁止）。
3. **JSONを書く**: `inbox/plan_T<ID>_v<次の版>.json`（下のスキーマ）。
4. **検証して取り込む**:
   ```
   ./ns validate plan inbox/plan_T003_v1.json
   ./ns import-plan inbox/plan_T003_v1.json
   ```
5. **止まる（チェックポイント）**: チャットで「価値の一文」「差別化の要点」「おすすめのタイトル案と理由」を
   短く伝え、画面でタイトル・構成・価格を選んで承認するよう案内して終わる。
   **`./ns approve-plan` を自分で実行してはいけない**。

## 設計の考え方

### なぜお金を払うのか（value_proposition / why_paid）
「役に立つ」では弱い。次のどれを **具体的に** 提供するかで書く:
- **時間の節約**: 公式資料○ページ・複数サイトを読む手間 → 10分で把握
- **お金の節約・損失回避**: 申請漏れ・手続きミス・買い間違いを防ぐ
- **判断の材料**: 自分がどのケースに当たるか分かる比較表・フローチャート
- **すぐ使える道具**: チェックリスト、テンプレート、試算表
`why_paid` には「無料の検索では手に入らない理由」を2つ以上。

### 差別化（differentiators、最低1つ）
書き手（依頼者）が **実際に用意できるもの** を優先し、`how_to_make` に作り方を具体的に書く。
- `primary_info`: 実際に手続きした記録、試した結果、スクショ、窓口に問い合わせた回答、自作アンケート
- `angle`: 特定の読者に絞る（例:「共働き・子2人の場合」）、時系列で並べ直す、失敗例から逆算する
- `diagram`: フローチャート、比較表、タイムライン（文章だけの競合との差が一目で分かる）
- `template` / `checklist` / `calculation` / `curation`
人間の作業が必要なもの（体験・取材・スクショ）は `description` にそう明記し、`effort` を正直に付ける。

### 無料／有料の境界（paywall）
- 無料部分で **信頼を作る**: 誰向けか、何が解決するか、そして **中身の質が分かる実物**（比較表の一部、
  手順の最初の1ステップを完全に）を見せる。予告だけの無料部分は買われない。
- 境界は **読者が「自分の場合はどうすれば？」と思った直後**、最も行動に直結する部分（全ケースの比較表、
  チェックリスト、具体手順、テンプレート）の手前に置く。
- 無料部分の最後に「有料部分で手に入るもの」を箇条書きで示す。
- `boundary_hook`: 境界直前に置く一文。煽らず、得られるものを具体的に言う。

### タイトル（titles、5案以上推奨・最低3案）
- 主要キーワードを前半に置く（Google検索の表示は全角30字前後で切れやすい）。
- 切り口を変える: 網羅型／対象者特定型／損失回避型／手順型／比較型など。`angle` に明記。
- 時期がある情報は「2026年版」「令和8年度」など年度を入れる。
- **誇大表現は使わない**: 「絶対」「誰でも」「完全攻略」「稼げる」「最強」、根拠のない数字は不可。

### 見出し構成（outlines、2案以上）
- 構成の型を変える（例: 手順型／ケース別比較型／Q&A型）。`concept` にどんな読者に合う型かを書く。
- 各案 5〜10 セクション。`paid` で無料／有料を明示（両方必要）。`points` に中身の要点。
- 無料セクションは paywall.free_part と、有料セクションは paid_part と整合させる。

### 価格（price）
- 競合の価格帯（確認済みのもの）と、提供価値（節約できる時間・お金）から決める。
- 実績ゼロの書き手が「まず1本売る」段階では、競合より少し低めの入口価格も選択肢。
  `rationale` に根拠、`alternatives` に代替案を入れる。価格はあとで実績を見て調整する前提。

### open_questions
人間にしか答えられないこと（実体験の有無、用意できるスクショ、対象読者の絞り方の好み）を書く。

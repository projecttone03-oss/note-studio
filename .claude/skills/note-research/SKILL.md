# 段階1: 需要リサーチ

ゴールは「1冊数百円でもいいので、まず実際に売れるテーマ」を見つけること。
派手さより **確実に買われる理由があるテーマ** を優先する。

## 手順

1. **過去の文脈を読む**: `./ns context` を実行し、既出テーマ（重複させない）と
   人間の判断ログ（何をなぜ却下・採用したか）を読んで、探索方針に反映する。
2. **探索方針を決める**: 依頼にジャンル指定があればそれに従う。なければ下の「探し方」から
   3〜4系統を選んで広く探す。方針は JSON の `brief` に書く。
   `references/books/_書籍リスト.md` で「使う段階」に1を含む書籍（売れるテーマの見つけ方・競合記事のレベルチェック・発想法）を
   `tools/pdftool find` で該当箇所だけ読み、使えそうな観点を方針に取り入れる（取り入れた場合は brief に書名を書く）。
   ただし書籍の方法が note内検索や X の自動収集を前提にしている場合は、ここの規約ルールを優先する。
3. **調べる**: WebSearch を20〜40回程度。候補を8〜12個ほど拾ってから、根拠が弱いものを落として
   **5〜8件** に絞る。
4. **JSONを書く**: `inbox/research_YYYYMMDD.json`（下のスキーマ）。
5. **検証して取り込む**:
   ```
   ./ns validate research inbox/research_YYYYMMDD.json
   ./ns import-research inbox/research_YYYYMMDD.json
   ```
6. **止まる（チェックポイント）**: チャットで上位候補を3行ずつ要約し、
   「`./ns serve` の画面（http://127.0.0.1:8765）で採用／保留／却下してください」と伝えて終わる。
   **`./ns decide` を自分で実行してはいけない**（人間の判断を代行しない）。

## 探し方（需要のシグナル）

| 系統 | 何を見るか | 検索例 |
|---|---|---|
| 制度変更・期限 | 公的機関の発表で「対象者が多い」「手続きが必要」「期限がある」もの。行動を迫られる人は情報にお金を払う | `2026年 改正 手続き 対象者`、`令和8年度 変更 申請 期限` |
| 繰り返される質問 | Q&Aサイトで同じ質問が何度も出ている＝公式情報が分かりにくい | `知恵袋 ○○ わからない`、`○○ 手続き どうすれば` |
| SNSで話題 | ニュース・まとめ記事経由で把握する（Xを直接スクレイピングしない） | `○○ SNSで話題 困惑`、`○○ 炎上 わかりにくい` |
| 既存の有料商品 | note・Brain・Tips・Kindle・Udemy に有料商品がある＝支払い意思がある証拠 | `site:note.com ○○ 有料`、`site:brain-market.com ○○` |
| 新しいツール・サービス | 登場直後で日本語の体系的な解説が少ないもの | `○○ 使い方 日本語 まとめ` |

## 「良質な有料記事が少ない」の判定

次のどれかに当てはまればギャップあり（`gap` に具体的に書く）:
- 有料記事が **ない**、または制度変更・仕様変更 **前の古い情報** のまま
- 無料情報は多いが **散らばっていて、判断に使える形に整理されていない**（比較表・手順・チェックリストがない）
- 公式資料はあるが **専門用語だらけで読めない**
- 既存の有料記事の価格に対して中身が薄い（タイトル・無料部分・レビューから推定できる範囲で）

「情報整理型」と相性が良いのは、記事の価値が **散らばった公開情報を、読者が意思決定・行動できる形に
まとめ直すこと** にあるテーマ。公開情報＋書き手自身の経験（一次情報）で書けるものを高く評価する。

## 避けるテーマ（候補に入れない、または `risks` に明記）

- 個別の税務相談・法律相談・医療判断が必要なもの（税理士法・弁護士法・医師法に触れうる）。
  「制度の仕組みと手順の整理」まではOK、「あなたの場合はこうすべき」はNG
- 「誰でも稼げる」系の情報商材、投資の売買推奨（誇大表現・景品表示法・金融商品取引法リスク）
- 書籍・有料講座・他人の有料記事の要約（著作権）
- 1週間で賞味期限が切れる速報ネタ、ゴシップ、特定個人に関する話題

## 規約・情報源のルール（厳守）

- **note.com**: robots.txt で `/search` と `/api/*` はクローラに禁止されている。
  **note内検索・APIには一切アクセスしない**。note記事は一般のWeb検索（`site:note.com`）で見つける。
  価格確認のために個別の公開記事ページを WebFetch で開くのは **1回のリサーチで合計5ページまで**。
  開いて確認できた価格だけ `price_verified: true`、検索スニペット由来の価格は `false`。
- **X（旧Twitter）**: スクレイピングしない。話題性はニュースやまとめ記事経由で把握する。
- **出典は実際にこのセッションで見たURLだけ**。URLや数値を推測で作らない。数値は出典にあるものだけ。
- 公的資料のPDFが WebFetch で読めないときは、結果の保存先パスを `tools/pdftool text <パス> 1 5` で読んで原文を確認する。
- 公的統計・官公庁（go.jp、e-Stat、自治体）・一次情報を優先。ブログやnote記事は `type` を正しく付けて区別する。
- 引用は主張の要約にとどめ、原文の長い転記はしない。

## スコアの付け方（各1〜5、アプリが重み付けして100点換算）

| キー | 5 | 3 | 1 |
|---|---|---|---|
| demand（需要） | 公的数字で対象者が数十万人以上 or 同じ質問が大量 | 一定の検索・質問がある | 根拠が薄い |
| gap（有料の空白） | 有料記事がほぼない／古い | 有料はあるが質・鮮度に難 | 良質な有料記事が多数 |
| willingness_to_pay（払う動機） | 読むことでお金・時間・失敗を明確に節約できる | 役立つが無料で我慢できる | 好奇心だけ |
| feasibility（書けるか） | 公開情報＋一般的な経験で書ける | 一部に取材・実体験が必要 | 専門資格・特殊な経験が必須 |
| longevity（寿命） | 1年以上売れる（毎年更新で継続も可） | 数か月 | 数週間 |

`score_rationale` には各スコアの理由を1〜2文ずつ、根拠（demand_evidence）と対応させて書く。

## JSONスキーマ

```json
{
  "genre": "おまかせ",
  "brief": "探索方針（どの系統をなぜ選んだか、過去の判断ログをどう反映したか）",
  "method": "手順の要約（検索回数、見たサイトの種類、確認できなかったこと）",
  "queries": ["実際に使った検索クエリ", "..."],
  "candidates": [
    {
      "title": "テーマ名（記事タイトルではなく、何についての記事か）",
      "summary": "1〜2文の概要",
      "target_reader": "想定読者（属性と状況を具体的に）",
      "reader_pain": "読者の悩み・なぜ今知りたいか",
      "keywords": ["想定検索キーワード", "2個以上"],
      "channels": ["Google検索", "X", "note内の回遊"],
      "demand_evidence": [
        {
          "claim": "需要を示す事実（数字は出典どおり）",
          "source": {"url": "https://...", "title": "ページタイトル", "publisher": "発行者",
                     "type": "official|primary|news|qa|sns|note|blog|other", "published": "2026-08"},
          "confidence": "high|medium|low"
        }
      ],
      "competitors": [
        {"title": "競合記事・商品名", "url": "https://...", "platform": "note|brain|tips|kindle|udemy|blog|other",
         "price": 500, "paid": true, "price_verified": false, "quality_note": "鮮度・網羅性など気づいた点"}
      ],
      "price_range": {"min": 300, "max": 980, "note": "競合の価格帯の根拠（確認済み件数など）"},
      "gap": "なぜ良質な有料記事が少ないと言えるか（具体的に）",
      "differentiation_hint": "差別化の芽（一次情報・切り口・図解など）",
      "primary_info_needed": "書き手が用意すべき一次情報（実体験、試算、スクショ、取材など）",
      "risks": ["法規制・誇大表現・鮮度などの注意点"],
      "scores": {"demand": 4, "gap": 3, "willingness_to_pay": 4, "feasibility": 4, "longevity": 3},
      "score_rationale": "各スコアの理由"
    }
  ]
}
```

競合が見つからなかった場合は `competitors: []` とし、`gap` に「どう探して見つからなかったか」を書く
（見つからない＝需要がない可能性もあるので、需要根拠とあわせて判断する）。
